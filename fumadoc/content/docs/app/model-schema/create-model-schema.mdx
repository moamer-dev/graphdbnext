# Create Model Schema

This guide shows you how to create new graph model schemas using the visual Plexus Builder canvas. Design your graph models interactively with nodes, relationships, and properties without writing code.

> [!IMPORTANT]
> Schema creation focuses on defining the structure of your graph model (nodes and relationships). For generating actual graph data from XML, see our [Graph Generation Guide](./generate-graph).

## Getting Started

### Access the Model Builder

1. **Navigate**: Dashboard → Model Schema → Create Model
2. **URL**: `/dashboard/graph/model/new`
3. **Requirements**: Model Builder module must be enabled in Settings

> [!NOTE]
> If you see "Model Builder module is not enabled," contact your administrator to enable it in Settings → Modules.

When you first open the model builder, you'll see:

- **Model Name Field**: Give your model a descriptive name

## Tools and Actions Palette

### Understanding Tools and Actions as Workflow Nodes

Tools and Actions are not just UI elements - they are **executable nodes** that become part of your graph generation workflow. When you add tools and actions to your canvas, you're building a workflow that will be executed to process XML data and generate your graph.

### Tools Palette

Tools are executable nodes that perform specific operations during graph generation:

#### Tool Categories
- **Search Functionality**: Find specific tools quickly
- **Category Organization**: Tools grouped by function

#### Available Tools
- **Data Processing**: Tools for transforming and processing XML data
- **Node Creation**: Tools that create graph nodes from XML elements
- **Relationship Building**: Tools that establish connections between nodes
- **Data Validation**: Tools for validating data and schema compliance

#### Tool Execution
- **Workflow Integration**: Tools become nodes in your execution workflow
- **Sequential Processing**: Tools execute in sequence as defined by connections
- **Data Flow**: Output from one tool becomes input for the next
- **Error Handling**: Tools can handle errors and exceptions during processing

### Actions Palette (Workflow Actions)

Actions are executable nodes that control the flow and behavior of your graph generation:

#### Action Categories
- **Search Actions**: Find specific workflow actions
- **Category Filter**: Filter actions by category

#### Workflow Actions
- **Control Flow**: Actions that control execution flow (conditions, loops)
- **Data Operations**: Actions for data manipulation and transformation
- **Validation Actions**: Actions for schema validation and checking
- **Export Actions**: Actions for exporting results and generating output

#### Action Execution
- **Conditional Logic**: Actions can make decisions based on data
- **Branching**: Create different execution paths based on conditions
- **Integration**: Actions integrate with external services and APIs
- **State Management**: Actions can maintain and modify workflow state

### Building Workflow Graphs

#### Creating Executable Workflows
1. **Add Tools**: Drag tools from the Tools palette to the canvas
2. **Add Actions**: Drag actions from the Actions palette to the canvas
3. **Connect Nodes**: Create connections between tools and actions
4. **Configure Nodes**: Set parameters and properties for each node
5. **Define Flow**: Establish the execution order with connections

#### Workflow Execution Process
- **Start Node**: Execution begins from designated root nodes
- **XML Processing**: Tools and actions process XML data sequentially
- **Graph Generation**: Nodes and relationships are created as the workflow executes
- **Result Output**: Final graph structure is generated based on workflow execution

#### Execution Context
- **XML Document**: Tools and actions have access to the XML being processed
- **Graph Context**: Current state of the graph being generated
- **Data Flow**: Data passes between connected nodes
- **Error Context**: Errors are handled and propagated through the workflow

### Workflow Integration

#### Combining Tools and Actions
- **Tool-Action Sequences**: Combine data processing with control flow
- **Conditional Processing**: Use actions to control when tools execute
- **Data Transformation**: Tools transform data, actions control the flow
- **Error Handling**: Actions can handle errors from tool execution

#### Workflow Execution Features
- **Run Workflow**: Execute the complete workflow from start to finish
- **Step-by-Step Debugging**: Execute workflow step by step for debugging
- **Error Recovery**: Handle and recover from execution errors
- **Result Validation**: Validate generated graph against expected results

## Model Creation Workflow

### 1. Name Your Model

Start by giving your model a meaningful name:

- **Field Location**: Top of the page
- **Requirements**: 
  - Must be unique among your models
  - Should describe the model's purpose
  - Examples: "Social Network", "Product Catalog", "Research Data"

### 2. Design Your Schema on Canvas

The visual canvas is where you'll build your graph model:

#### Adding Nodes
- **Tool**: Select "Add Node" from the toolbar
- **Action**: Click anywhere on the canvas to place a node
- **Result**: A new node appears ready for customization

#### Creating Relationships
- **Tool**: Select "Add Relationship" from the toolbar
- **Action**: Click and drag from one node to another
- **Result**: A relationship line connects the two nodes

#### Editing Properties
- **Action**: Click any node or relationship
- **Result**: Properties panel opens for customization. (Make sure to enable "Editor" mode in the toolbar)
- **Options**: Add properties, set data types, define requirements

### 3. Configure Node Properties

Each node in your graph represents a type of entity:

#### Basic Properties
- **Node Name**: The identifier for this node type
- **Properties**: Attributes that nodes of this type will have

#### Property Types
- **Text**: For names, descriptions, and other text data
- **Number**: For counts, measurements, and numeric values
- **Date**: For timestamps and dates
- **Boolean**: For true/false values
- **List**: For multiple values of the same type

#### Required vs Optional
- **Required**: Must have a value for every node instance
- **Optional**: Can be left empty for some node instances

### 4. Configure Relationships

Relationships define how nodes are connected:

#### Relationship Properties
- **Relationship Name**: Descriptive name for the connection
- **Direction**: Whether it's one-way or bidirectional
- **Cardinality**: The number of relationships (e.g., one-to-many, many-to-many)

#### Relationship Examples
- **Person** → [WRITES] → **Document**
- **Product** → [BELONGS_TO] → **Category**
- **User** → [FOLLOWS] → **User**

### 5. Save Your Model

Once you're satisfied with your design:

#### Save Process
1. **Click Save**: Located in the top toolbar
2. **Validation**: System checks your schema for completeness
3. **Confirmation**: Model is saved to your library
4. **Redirect**: You're taken to the model detail view

#### Auto-Save
- **Changes Detected**: System tracks unsaved changes
- **Warning**: Alerts you if you try to leave without saving
- **Recovery**: Helps prevent losing your work
