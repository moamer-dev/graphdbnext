# XML Rules Assistant

The XML Rules Assistant is a specialized AI agent focused exclusively on helping users configure XML analysis rules for importing XML files into graph databases. It provides expert guidance on setting up ignored elements, reference attributes, pattern rules, and other analysis configurations.

## Purpose

The assistant serves as a dedicated expert for XML analysis rule configuration, helping users optimize how XML documents are processed during the import process. It has a narrowly focused scope that ensures deep expertise in XML analysis rules while avoiding scope creep into general XML technologies.

## Scope and Limitations

### **What the Assistant CAN Do:**
1. **Discuss XML Analysis Rules**: Explain what rules mean and how they work
2. **Set/Suggest Rules**: Propose rules for specific XML structures
3. **Update/Modify Rules**: Change existing rules based on user feedback

### **Available XML Analysis Rules:**
- **Ignored Elements**: Elements to completely ignore during analysis
- **Ignored Subtrees**: Elements whose children should be ignored
- **Reference Attributes**: Attributes that create cross-references (id, target, corresp, etc.)
- **Pattern Rules**: Attributes indicating alternatives, annotations, translations, or choices
- **Relationship Type Mappings**: How parent-child element relationships should be typed
- **Text Content Rules**: Whether elements should be processed at character-level or sign-level

### **What the Assistant CANNOT Do:**
- XML validation (DTD, XSD, Schematron, RelaxNG)
- Explain XPath, XQuery, XSLT, or other XML query/transformation technologies
- Provide information about XML tools, libraries, or general XML programming
- Answer questions about XML standards, specifications, or formats
- Discuss topics unrelated to configuring XML analysis rules for import

## Key Capabilities

### Rule Configuration Expertise
- **Ignored Elements**: Identifies elements that should be excluded from processing
- **Reference Detection**: Recognizes attributes that create cross-references between elements
- **Pattern Recognition**: Identifies patterns for alternatives, annotations, and translations
- **Hierarchy Analysis**: Analyzes parent-child relationships for optimal processing

### Domain-Specific Knowledge
- **Scholarly XML**: Expertise in TEI, edXML, and academic XML formats
- **Research Patterns**: Understanding of common research document patterns
- **Import Optimization**: Knowledge of graph database import requirements
- **Performance Considerations**: Awareness of processing performance implications

### Rule Optimization
- **Processing Efficiency**: Suggests rules that optimize processing performance

## Configuration and Usage

### Assistant Initialization
```typescript
import { XmlRulesAssistant } from '@plexus/builder/ai/agents'

const assistant = new XmlRulesAssistant({
  model: chatModel,
  settings: aiSettings
})
```

### Rules Configuration Request
```typescript
const rules = await assistant.configureRules({
  xmlStructure: {
    elements: ["TEI", "teiHeader", "fileDesc", "titleStmt", "title", "author", "text", "body", "div", "p", "note"],
    attributes: ["xml:id", "type", "n", "corresp", "target", "resp"],

      "TEI": ["teiHeader", "text"],
      "teiHeader": ["fileDesc"],
      "text": ["body"],
      "body": ["div", "p"],

    }
  },
  processingGoals: {
    targetGraph: "bibliographic_network",
    performancePriority: "speed",
    qualityRequirements: "high"
  }
})
```

## Rule Types and Usage

### Ignored Elements
**Purpose**: Exclude elements from processing to improve performance and focus on relevant content
**Common Examples**:
- Metadata elements that don't need graph representation
- Formatting elements that don't contain semantic content
- Temporary or processing elements

**Configuration Example**:
```typescript
{
  ignoredElements: ["teiHeader", "revisionDesc"]
}
```

### Ignored Subtrees
**Purpose**: Ignore children of specific elements while processing the parent
**Common Examples**:
- Complex metadata structures
- Formatting containers
- Processing instructions

**Configuration Example**:
```typescript
{
  ignoredSubtrees: ["teiHeader", "encodingDesc"]
}
```

### Reference Attributes
**Purpose**: Identify attributes that create cross-references between elements
**Common Examples**:
- `xml:id` and `target` for element references
- `corresp` for correspondence relationships
- `ref` for general references
- `sameAs` for identity relationships

**Configuration Example**:
```typescript
{
  referenceAttributes: ["xml:id", "target", "corresp", "ref", "sameAs"]
}
```

### Pattern Rules
**Purpose**: Identify special patterns in XML attributes
**Categories**:
- **Alternative Attributes**: Elements representing alternatives or choices
- **Annotation Attributes**: Elements that annotate other elements
- **Translation Attributes**: Elements that provide translations
- **Choice Indicators**: Attributes that indicate choices or options

**Configuration Example**:
```typescript
{
  patternRules: {
    alternativeAttributes: ["alt", "choice"],
    annotationAttributes: ["resp", "type"],
    translationAttributes: ["translation", "lang"],
    choiceIndicators: ["select", "option"]
  }
}
```

### Relationship Type Mappings
**Purpose**: Define how parent-child relationships should be typed in the graph
**Common Examples**:
- Document structure relationships
- Content containment relationships
- Semantic relationships

**Configuration Example**:
```typescript
{
  relationshipTypeMappings: {
    "div": ["CONTAINS", "HAS_SECTION"],
    "p": ["CONTAINS", "HAS_PARAGRAPH"],
    "note": ["ANNOTATES", "HAS_NOTE"]
  }
}
```

### Text Content Rules
**Purpose**: Specify processing level for text content
**Categories**:
- **Character-Level Elements**: Elements that need character-by-character processing
- **Sign-Level Elements**: Elements that can be processed at the sign/word level

**Configuration Example**:
```typescript
{
  textContentRules: {
    characterLevelElements: ["w", "c"],
    signLevelElements: ["p", "div"]
  }
}
```
