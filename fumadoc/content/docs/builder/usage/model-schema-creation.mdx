# Model Schema Creation

Model Schema Creation in Plexus Builder allows you to design and construct graph database schemas visually using an intuitive drag-and-drop interface. This powerful feature enables researchers to create comprehensive data models without writing code, while leveraging AI assistance and semantic terminology integration.

## Overview

The Model Builder provides a visual canvas where you can:
- **Design Node Types**: Create and configure different node types with properties
- **Define Relationships**: Establish connections between node types with proper cardinality
- **Apply Semantic Standards**: Integrate with TIB terminology service for consistent naming
- **Get AI Assistance**: Use AI agents to suggest optimal schema designs
- **Validate Schemas**: Ensure schema completeness and consistency

## Getting Started

### Accessing the Model Builder

1. **Navigate to Builder**: From the main interface, select the Model Builder
2. **Create New Schema**: Choose "Create New Schema" or start with a template
3. **Select Canvas**: The visual canvas will appear with the node palette and configuration panels

### Interface Components

#### Main Canvas
- **Node Palette**: Drag node types onto the canvas
- **Workspace**: Design your schema visually
- **Connection Tools**: Create relationships between nodes
- **Configuration Panels**: Edit node and relationship properties

#### Side Panels
- **Node Editor**: Configure selected node properties
- **Relationship Editor**: Define connection parameters
- **TIB Terminology Panel**: Access standardized terminology
- **Schema Validation**: Check schema completeness

## Creating Node Types

### Adding Nodes to the Canvas

1. **Select Node Type**: From the node palette, choose a node type
2. **Drag to Canvas**: Drag the node onto the canvas
3. **Position Node**: Arrange nodes in a logical layout
4. **Configure Properties**: Open the Node Editor to set properties

### Node Configuration

#### Basic Properties
- **Label**: Display name for the node (e.g., "Person", "Publication")
- **Type**: Internal node type identifier
- **Description**: Purpose and context of the node

#### Property Definition
- **Property Name**: Internal property identifier
- **Display Name**: User-friendly property name
- **Data Type**: String, number, boolean, date, array, or object
- **Required**: Whether the property is mandatory
- **Default Value**: Default value for the property
- **Validation Rules**: Constraints and validation patterns

#### Example Node Configuration
```typescript
// Person Node
{
  label: "Person",
  type: "Person",
  description: "Individual person in the research network",
  properties: [
    {
      name: "name",
      displayName: "Full Name",
      type: "string",
      required: true,
      validation: { minLength: 1, maxLength: 255 }
    },
    {
      name: "email",
      displayName: "Email Address",
      type: "string",
      required: false,
      validation: { pattern: "^[^@]+@[^@]+\.[^@]+$" }
    },
    {
      name: "orcid",
      displayName: "ORCID Identifier",
      type: "string",
      required: false,
      validation: { pattern: "^\\d{4}-\\d{4}-\\d{4}-\\d{3}[\\dX]$" }
    }
  ]
}
```

### AI-Assisted Node Creation

#### Node Property Suggestion Agent
1. **Select Node**: Click on a node in the canvas
2. **Open AI Assistant**: Click the AI Assistant button in the Node Editor
3. **Get Suggestions**: The AI will suggest relevant properties based on:
   - Node type and label
   - Domain context
   - Common patterns for similar nodes
   - Best practices for graph databases

#### Example AI Suggestions
For a "Publication" node, the AI might suggest:
- `title` (string, required) - Publication title
- `publicationDate` (date, required) - Publication date
- `doi` (string, optional) - Digital Object Identifier
- `abstract` (string, optional) - Publication abstract
- `authors` (array, optional) - List of author references
- `venue` (string, optional) - Publication venue

## Creating Relationships

### Adding Relationships

1. **Select Source Node**: Click on the source node
2. **Create Relationship**: Drag from the source to the target node
3. **Configure Relationship**: Open the Relationship Editor
4. **Set Properties**: Define relationship type and properties

### Relationship Configuration

#### Basic Properties
- **Type**: Relationship type (e.g., "AUTHORED", "PUBLISHED_IN")
- **Direction**: Direction of the relationship (source → target)
- **Cardinality**: One-to-one, one-to-many, or many-to-many
- **Description**: Purpose and meaning of the relationship

#### Relationship Properties
- **Property Name**: Internal property identifier
- **Data Type**: String, number, boolean, or date
- **Required**: Whether the property is mandatory
- **Default Value**: Default value for the property

#### Example Relationship Configuration
```typescript
// AUTHORED Relationship
{
  type: "AUTHORED",
  from: "Person",
  to: "Publication",
  direction: "outgoing",
  cardinality: "one-to-many",
  description: "Person authored the publication",
  properties: [
    {
      name: "authorOrder",
      displayName: "Author Order",
      type: "number",
      required: false,
      validation: { min: 1 }
    },
    {
      name: "contributionType",
      displayName: "Contribution Type",
      type: "string",
      required: false,
      validation: { enum: ["primary", "secondary", "contributor"] }
    }
  ]
}
```

### AI-Assisted Relationship Creation

#### Relationship Recommendation Agent
1. **Select Two Nodes**: Click on two nodes to connect
2. **Open AI Assistant**: Click the AI Assistant button
3. **Get Recommendations**: The AI will suggest:
   - Appropriate relationship types
   - Optimal cardinality
   - Relevant properties
   - Confidence scores for each suggestion

#### Example AI Recommendations
For connecting "Person" to "Publication":
- `AUTHORED` (one-to-many, high confidence) - Person authored the publication
- `REVIEWED` (one-to-many, medium confidence) - Person reviewed the publication
- `CITED` (many-to-many, medium confidence) - Person cited the publication

## Best Practices

### Schema Design Principles

#### Semantic Clarity
- **Meaningful Names**: Use names that clearly express meaning
- **Consistent Terminology**: Maintain consistent naming throughout
- **Domain Relevance**: Use terminology relevant to your domain
- **Avoid Ambiguity**: Choose names that minimize confusion

#### Structural Design
- **Normalization**: Apply appropriate normalization to avoid redundancy
- **Modularity**: Design schemas in modular, reusable components
- **Extensibility**: Build schemas that can evolve with changing requirements
- **Maintainability**: Design schemas that are easy to understand and modify

#### Performance Considerations
- **Query Patterns**: Design schemas to support common query patterns
- **Indexing Strategy**: Consider indexing requirements during design
- **Data Volume**: Plan for expected data volume and growth
- **Access Patterns**: Optimize for expected access patterns

### Common Pitfalls to Avoid

#### Design Mistakes
- **Over-normalization**: Excessive normalization can hurt performance
- **Under-normalization**: Insufficient normalization can cause data redundancy
- **Poor Naming**: Unclear or inconsistent naming creates confusion
- **Ignoring Cardinality**: Incorrect cardinality leads to data integrity issues

#### Performance Issues
- **Deep Hierarchies**: Excessively deep relationship hierarchies
- **Large Properties**: Storing large data in node properties
- **Missing Indexes**: Forgetting to plan for indexing requirements
- **Inefficient Queries**: Not considering query patterns during design
