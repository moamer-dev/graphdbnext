# Database Models & Types

Plexus Builder uses a comprehensive type system to represent graph schemas, workflows, and application state. All models are defined with TypeScript to ensure type safety and developer experience.

## Core Graph Models

### Node Model

The core node representation in the graph schema:

```typescript
export interface Node {
  id: string                    // Unique identifier
  label: string                  // Display label (e.g., "Person", "Publication")
  type: string                   // Internal type identifier
  properties: Property[]        // Node property definitions
  position: { x: number; y: number }  // Canvas position
  groupId?: string               // Optional group membership
  order?: number                 // Order for ungrouped nodes
  data?: Record<string, unknown> // Additional metadata
}
```

**Key Characteristics**:
- **Unique ID**: Each node has a unique identifier for reference
- **Label vs Type**: Label is user-facing, type is internal
- **Position**: Canvas position for visual representation
- **Properties**: Schema definition for node properties

### Property Model

Properties define the schema for node and relationship attributes:

```typescript
export interface Property {
  key: string                    // Property key/name
  type: 'string' | 'number' | 'boolean' | 'date' | 'array' | 'object'
  required: boolean              // Whether property is mandatory
  defaultValue?: unknown         // Default value for new instances
  description?: string           // Property description
}
```

**Property Types**:
- **string**: Text values and identifiers
- **number**: Numeric values (integers, floats)
- **boolean**: True/false values
- **date**: Date/time values
- **array**: Arrays of values
- **object**: Complex nested objects

### Relationship Model

Relationships define connections between nodes:

```typescript
export interface Relationship {
  id: string                    // Unique relationship identifier
  type: string                  // Relationship type (e.g., "AUTHORED", "CONTAINS")
  from: string                  // Source node ID
  to: string                    // Target node ID
  properties?: Property[]       // Relationship properties
  cardinality?: 'one-to-one' | 'one-to-many' | 'many-to-many'
  data?: Record<string, unknown> // Additional metadata
}
```

**Cardinality Types**:
- **one-to-one**: Each source node connects to exactly one target node
- **one-to-many**: One source node can connect to multiple target nodes
- **many-to-many**: Multiple source nodes can connect to multiple target nodes

### Relationship Type Model

Reusable relationship type definitions:

```typescript
export interface RelationshipType {
  type: string                  // Relationship type name
  properties?: Property[]       // Standard properties for this type
  cardinality?: 'one-to-one' | 'one-to-many' | 'many-to-many'
}
```

## Type Safety and Validation

### Zod Schemas

Runtime validation schemas for critical types:

```typescript
import { z } from 'zod'

// Node validation schema
export const NodeSchema = z.object({
  id: z.string(),
  label: z.string(),
  type: z.string(),
  properties: z.array(PropertySchema),
  position: z.object({ x: z.number(), y: z.number() }),
  groupId: z.string().optional(),
  order: z.number().optional(),
  data: z.record(z.unknown()).optional()
})

// Property validation schema
export const PropertySchema = z.object({
  key: z.string(),
  type: z.enum(['string', 'number', 'boolean', 'date', 'array', 'object']),
  required: z.boolean(),
  defaultValue: z.unknown().optional(),
  description: z.string().optional()
})
```

This comprehensive type system ensures type safety throughout the application while providing clear contracts for all data structures and APIs.
