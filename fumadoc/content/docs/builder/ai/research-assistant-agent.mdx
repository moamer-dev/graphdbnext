# Research Assistant Agent

The Research Assistant Agent is a comprehensive AI-powered assistant that helps researchers understand, design, and optimize graph database schemas and workflows. It provides expert guidance across the entire Plexus Builder ecosystem, from XML import wizard navigation to advanced workflow design.

## Purpose

The agent serves as a knowledgeable research companion that can assist with schema design, workflow creation, XML processing, and general graph database concepts. It combines deep domain expertise with practical application knowledge to help researchers succeed with their data modeling and analysis projects.

## Key Capabilities

### Schema Design Assistance
- **Node and Relationship Creation**: Help users create and modify graph schemas
- **Schema Optimization**: Suggest improvements and optimizations for existing schemas
- **Best Practice Guidance**: Provide guidance on graph database design principles
- **Domain-Specific Expertise**: Apply knowledge specific to research domains

### Workflow Design Support
- **Tool Selection**: Guide users in choosing appropriate workflow tools
- **Action Configuration**: Assist with action configuration and parameter setup
- **Workflow Optimization**: Suggest optimizations for workflow performance and efficiency
- **Troubleshooting**: Help identify and resolve workflow issues

### XML Import Wizard Guidance
- **Wizard Navigation**: Guide users through the XML import wizard steps
- **Configuration Assistance**: Help with wizard configuration options
- **Import Optimization**: Suggest optimizations for XML import processes
- **Error Resolution**: Assist with import-related issues and errors

### Educational Support
- **Concept Explanation**: Explain graph database concepts clearly for researchers
- **Best Practice Education**: Teach best practices for data modeling and analysis
- **Tool Usage Guidance**: Explain how to use various Plexus Builder features
- **Domain Knowledge**: Provide domain-specific knowledge and insights

## Integration with Application Tools

### Model Builder Tools
The agent has access to application tools that allow it to interact directly with the Plexus Builder interface:

**Schema Management Tools**:
- `create_node`: Create new nodes in the schema
- `create_relationship`: Create relationships between nodes
- `set_root_node`: Set the entry point for XML processing
- `get_workflow_registry`: Access available workflow components

**Contextual Tools**:
- `get_current_schema`: Retrieve current schema information
- `get_workflow_state`: Access current workflow state
- `validate_schema`: Validate schema completeness and consistency

## Context Awareness

### Application Context
The agent maintains awareness of:
- **Current View**: Whether user is in import wizard, Plexus Builder, or workflow builder
- **Schema State**: Current nodes, relationships, and their properties
- **Selection State**: Currently selected nodes or relationships
- **Workflow State**: Current workflow configuration and components

### User History
- **Conversation History**: Maintains context of ongoing conversations
- **User Preferences**: Learns from user interactions and preferences
- **Project Context**: Understands project-specific requirements and constraints
- **Domain Knowledge**: Builds domain-specific knowledge over time

## Configuration and Usage

### Agent Initialization
```typescript
import { ResearchAssistantAgent } from '@plexus/builder/ai/agents'

const agent = new ResearchAssistantAgent({
  model: chatModel,
  settings: aiSettings,
  toolContext: toolExecutionContext,
  appContext: {
    currentView: 'plexus-builder',
    currentState: {
      nodeCount: 15,
      relationshipCount: 23,
      selectedNodeId: 'node-123',
      nodes: [
        { label: 'Person', type: 'Author', id: 'node-123' },
        { label: 'Publication', type: 'Paper', id: 'node-456' }
      ]
    }
  }
})
```

### Interaction Example
```typescript
const response = await agent.invoke(
  "I need to create a relationship between my Person and Publication nodes to represent authorship. What's the best way to do this?",
  conversationHistory,
  toolContext,
  appContext
)
```

## Use Case Scenarios

### Schema Design Sessions
**User Query**: "I'm designing a schema for bibliographic data. What nodes and relationships should I include?"

**Agent Response**:
- Analyzes current schema context
- Suggests appropriate node types (Person, Publication, Journal, Institution)
- Recommends relationship types (AUTHORED, PUBLISHED_IN, AFFILIATED_WITH)
- Provides best practice guidance for bibliographic schemas
- May use `create_node` and `create_relationship` tools to help build the schema

### Workflow Design Assistance
**User Query**: "How do I create a workflow that processes TEI documents and extracts author information?"

**Agent Response**:
- Explains appropriate tools (tool:if, tool:switch for conditional processing)
- Recommends specialized actions (action:create-node-complete, action:create-token-nodes)
- Provides step-by-step workflow construction guidance
- May use `get_workflow_registry` to show available components

### XML Import Wizard Help
**User Query**: "I'm stuck on the mapping configuration step. How do I map XML attributes to graph properties?"

**Agent Response**:
- Provides step-by-step guidance for the mapping configuration
- Explains the relationship between XML attributes and graph properties
- Suggests optimal mapping strategies for the user's XML structure
- Offers troubleshooting advice for common mapping issues

### General Concept Questions
**User Query**: "What's the difference between one-to-many and many-to-many relationships in graph databases?"

**Agent Response**:
- Provides clear, researcher-friendly explanation of relationship cardinality
- Gives examples relevant to research domains
- Explains implications for query patterns and performance
- Suggests when to use each type of relationship
