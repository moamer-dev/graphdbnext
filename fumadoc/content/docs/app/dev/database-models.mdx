# Database Models

Plexus Platform uses a dual-database architecture: PostgreSQL for application metadata and user data, and graph databases (Neo4j/Memgraph) for graph data storage.

## PostgreSQL Schema

### Core Entities

#### User Management
```prisma
model User {
  id            String        @id @default(cuid())
  email         String        @unique
  password      String
  name          String?
  role          UserRole      @default(USER)
  emailVerified DateTime?
  createdAt     DateTime      @default(now())
  updatedAt     DateTime      @updatedAt
  
  // Relations
  models        Model[]
  savedQueries  SavedQuery[]
  workflows     Workflow[]
  accounts      Account[]
  sessions      Session[]
  userSettings  UserSettings?
}

enum UserRole {
  USER
  ADMIN
}
```

#### Authentication
```prisma
model Account {
  id                String  @id @default(cuid())
  userId            String
  type              String
  provider          String
  providerAccountId String
  refresh_token     String? @db.Text
  access_token      String? @db.Text
  expires_at        Int?
  token_type        String?
  scope             String?
  id_token          String? @db.Text
  session_state     String?
  
  user              User    @relation(fields: [userId], references: [id], onDelete: Cascade)
  
  @@unique([provider, providerAccountId])
}

model Session {
  id           String   @id @default(cuid())
  sessionToken String   @unique
  userId       String
  expires      DateTime
  user         User     @relation(fields: [userId], references: [id], onDelete: Cascade)
}
```

### Graph Schema Models

#### Model Schema Management
```prisma
model Model {
  id          String   @id @default(cuid())
  name        String
  description String?
  schema      Json     // Graph schema definition
  isPublic    Boolean  @default(false)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  
  // Relations
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  workflows   Workflow[]
  
  @@index([userId])
  @@index([isPublic])
}
```

#### Workflow Management
```prisma
model Workflow {
  id          String   @id @default(cuid())
  name        String
  description String?
  definition  Json     // Workflow definition (tools, actions, connections)
  isActive    Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  
  // Relations
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  modelId     String
  model       Model    @relation(fields: [modelId], references: [id], onDelete: Cascade)
  
  @@index([userId])
  @@index([modelId])
}
```

#### Query Management
```prisma
model SavedQuery {
  id          String   @id @default(cuid())
  name        String
  description String?
  query       String   // Cypher query
  category    String?
  isPublic    Boolean  @default(false)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  
  // Relations
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  
  @@index([userId])
  @@index([category])
  @@index([isPublic])
}
```

#### Relationship Structure
```cypher
// Generic relationship structure
CREATE (a)-[r:RELATIONSHIP_TYPE {
  id: "unique_identifier",
  properties: {
    weight: 1.0,
    created_at: datetime(),
    updated_at: datetime()
  }
}]->(b)
```

### Schema-Driven Graph Structure

#### Dynamic Schema Application
The graph database follows a schema-driven approach where:
1. **Model Schema** defines node types and relationships
2. **XML Data** is processed according to the schema
3. **Tools and Actions** transform XML into graph elements
4. **Root Nodes** determine traversal starting points

## Database Optimization

### Indexing Strategy

#### PostgreSQL Indexes
```sql
-- User performance indexes
CREATE INDEX idx_user_email ON users(email);
CREATE INDEX idx_user_role ON users(role);
CREATE INDEX idx_user_created_at ON users(created_at);

-- Model performance indexes
CREATE INDEX idx_model_user_id ON models(user_id);
CREATE INDEX idx_model_is_public ON models(is_public);
CREATE INDEX idx_model_created_at ON models(created_at);

-- Query performance indexes
CREATE INDEX idx_saved_query_user_id ON saved_queries(user_id);
CREATE INDEX idx_saved_query_category ON saved_queries(category);
CREATE INDEX idx_saved_query_is_public ON saved_queries(is_public);

-- Workflow performance indexes
CREATE INDEX idx_workflow_user_id ON workflows(user_id);
CREATE INDEX idx_workflow_model_id ON workflows(model_id);
CREATE INDEX idx_workflow_is_active ON workflows(is_active);
```

#### Graph Database Indexes
```cypher
-- Node indexes for performance
CREATE INDEX node_id_index FOR (n:Node) ON (n.id);
CREATE INDEX node_label_index FOR (n) ON (n.label);
CREATE INDEX node_type_index FOR (n) ON (n.type);

-- Relationship indexes
CREATE INDEX rel_id_index FOR ()-[r]-() ON (r.id);
CREATE INDEX rel_type_index FOR ()-[r]-() ON (r.type);

-- Composite indexes for common queries
CREATE INDEX node_label_type_index FOR (n:Node) ON (n.label, n.type);
```

### Query Optimization

#### Prisma Query Optimization
```typescript
// Efficient query with includes and selects
const models = await prisma.model.findMany({
  where: {
    userId: userId,
    isPublic: false
  },
  include: {
    workflows: {
      where: {
        isActive: true
      },
      select: {
        id: true,
        name: true,
        updatedAt: true
      }
    }
  },
  orderBy: {
    updatedAt: 'desc'
  }
});
```

#### Graph Query Optimization
```cypher
// Optimized query with proper indexing
MATCH (n:Node {type: $nodeType})
WHERE n.property = $value
WITH n
MATCH (n)-[r:RELATIONSHIP_TYPE]->(m:Node)
WHERE m.type = $targetType
RETURN n, r, m
LIMIT 100;
```

## Security Considerations

### Data Protection
- **Encryption**: Sensitive data encrypted at rest
- **Access Control**: Role-based data access
- **Audit Trail**: Data modification logging
- **Privacy Compliance**: GDPR and privacy regulations

### Query Security
- **Parameterized Queries**: SQL injection prevention
- **Query Limits**: Resource usage controls
- **Input Validation**: Comprehensive input sanitization
- **Rate Limiting**: Query rate limiting

This database architecture provides a robust foundation for the Plexus Platform, ensuring data integrity, performance, and scalability while maintaining clear separation between application metadata and graph data.
