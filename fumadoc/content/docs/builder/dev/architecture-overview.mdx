# Architecture Overview

Plexus Builder is built with a modular, component-based architecture that separates concerns across multiple layers. The system follows React patterns with Zustand for state management and a centralized registry system for workflow components.

## Core Architecture Principles

### 1. Component-Based Design
- **Modular Components**: Each major feature is a self-contained component
- **Reusable Patterns**: Common patterns extracted into shared components
- **Clear Boundaries**: Well-defined interfaces between components

### 2. Centralized State Management
- **Zustand Stores**: Lightweight, performant state management
- **Store Separation**: Each major feature has its own store
- **Cross-Store Communication**: Stores communicate through actions and selectors

### 3. Registry Pattern
- **Centralized Registry**: Single source of truth for workflow components
- **Dynamic Registration**: Components register themselves at runtime
- **Type Safety**: Full TypeScript support for registry operations

### 4. Service Layer Architecture
- **Separation of Concerns**: Business logic separated from UI logic
- **Dependency Injection**: Services injected into components
- **Testable Design**: Services easily testable in isolation

## Key Architectural Components

### 1. Workflow Registry System

The workflow registry is the central hub for managing all workflow components:

```typescript
import { ActionDefinition, ToolDefinition, CategoryMetadata } from './types'
import { Boxes } from 'lucide-react'

class WorkflowRegistry {
  private actions: Map<string, ActionDefinition> = new Map()
  private tools: Map<string, ToolDefinition> = new Map()
  private actionCategories: Map<string, CategoryMetadata> = new Map()
  private toolCategories: Map<string, CategoryMetadata> = new Map()

  registerAction(definition: ActionDefinition) {
    this.actions.set(definition.id, definition)
  }

  registerTool(definition: ToolDefinition) {
    this.tools.set(definition.id, definition)
  }

  registerActionCategory(category: CategoryMetadata) {
    this.actionCategories.set(category.id, category)
  }

  registerToolCategory(category: CategoryMetadata) {
    this.toolCategories.set(category.id, category)
  }

  getAction(id: string): ActionDefinition | undefined {
    return this.actions.get(id)
  }

  getTool(id: string): ToolDefinition | undefined {
    return this.tools.get(id)
  }

  getAllActions(): ActionDefinition[] {
    return Array.from(this.actions.values())
  }

  getAllTools(): ToolDefinition[] {
    return Array.from(this.tools.values())
  }

  getActionCategories(): CategoryMetadata[] {
    const registered = Array.from(this.actionCategories.values())
    const usedIds = new Set(registered.map(c => c.id))
    
    // Add any used but unregistered categories
    this.getAllActions().forEach(action => {
      if (action.metadata.category && !usedIds.has(action.metadata.category)) {
        registered.push({
          id: action.metadata.category,
          label: action.metadata.category,
          icon: Boxes as any
        })
        usedIds.add(action.metadata.category)
      }
    })
    
    return registered.sort((a, b) => (a.order ?? 999) - (b.order ?? 999))
  }
}
```

**Key Features**:
- **Dynamic Registration**: Components register themselves at import time
- **Type Safety**: Full TypeScript support for all registry operations
- **Category Management**: Automatic categorization of components
- **Metadata Support**: Rich metadata for UI generation

// TIB Terminology Service
import type { TibOntology, TibClass, TibProperty, TibApiResponse } from '../types/semanticTypes'

class LRUCache<T> {
  private cache: Map<string, { value: T; timestamp: number }>
  private maxSize: number
  private ttl: number

  constructor(maxSize: number = 100, ttlMinutes: number = 30) {
    this.cache = new Map()
    this.maxSize = maxSize
    this.ttl = ttlMinutes * 60 * 1000
  }

  get(key: string): T | null {
    const item = this.cache.get(key)
    if (!item) return null

    // Check if expired
    if (Date.now() - item.timestamp > this.ttl) {
      this.cache.delete(key)
      return null
    }

    // Move to end (LRU)
    this.cache.delete(key)
    this.cache.set(key, item)
    return item.value
  }

  set(key: string, value: T): void {
    // Remove oldest if at capacity
    if (this.cache.size >= this.maxSize) {
      const firstKey = this.cache.keys().next().value
      if (firstKey !== undefined) {
        this.cache.delete(firstKey)
      }
    }

    this.cache.set(key, { value, timestamp: Date.now() })
  }
}

## Performance Considerations

### 1. State Management Performance
- **Selective Subscriptions**: Components only subscribe to needed state slices
- **Shallow Comparisons**: Zustand uses shallow comparisons for performance
- **Memoized Selectors**: Expensive computations memoized in selectors

### 2. Rendering Performance
- **React.memo**: Components memoized to prevent unnecessary re-renders
- **useCallback/useMemo**: Hooks used to optimize expensive operations
- **Virtualization**: Large lists virtualized when needed

### 3. Memory Management
- **Cleanup Functions**: Proper cleanup in useEffect hooks
- **Weak References**: Used where appropriate for large data structures
- **Lazy Loading**: Components loaded on-demand when possible

## Security Architecture

### 1. Input Validation
- **Zod Schemas**: All external inputs validated with Zod schemas
- **Type Safety**: TypeScript provides compile-time type checking
- **Runtime Validation**: Additional runtime validation for critical operations

### 2. AI Integration Security
- **API Key Management**: Secure API key storage and management
- **Content Filtering**: AI responses filtered for malicious content
- **Rate Limiting**: Built-in rate limiting for AI API calls

### 3. Data Privacy
- **Local Processing**: XML data processed locally when possible
- **Minimal Data Sharing**: Only necessary data shared with external services
- **User Control**: Users control what data is shared with AI services

## Extensibility Architecture

### 1. Plugin System
- **Registry Pattern**: New components registered through registry
- **Type Extensions**: TypeScript types extended for new components
- **Hook Integration**: New functionality integrated through hooks

### 2. Custom Actions/Tools
- **Definition API**: Clear API for defining new actions and tools
- **Execution Interface**: Standard interface for execution logic
- **Configuration Schema**: Schema-based configuration UI generation

### 3. Theme and Styling
- **CSS Variables**: Theme customization through CSS variables
- **Component Overrides**: Components can be styled through CSS classes
- **Icon Customization**: Icons can be customized through registry

This architecture provides a solid foundation for building complex graph database workflows while maintaining code quality, performance, and extensibility.
